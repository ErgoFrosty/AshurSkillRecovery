# Ashur Skill Recovery

Привязанный к владельцу дневник восстановления для Project Zomboid Build
42.20. Он записывает опыт навыков и рецепты, изученные после создания
персонажа, а затем позволяет другому персонажу того же игрока восстановить этот
прогресс.

Это репозиторий разработки. Тестовые сборки используют ID
`AshurSkillRecoveryDev`, релизные — `AshurSkillRecovery`.

English documentation: [README.md](README.md).

## Как это работает

1. Создайте дневник восстановления из блокнота/дневника, клея и ниток,
   бечёвки, лески либо зубной нити.
2. Держите его в инвентаре персонажа и через контекстное меню записывайте или
   восстанавливайте прогресс, а также переименовывайте дневник.
3. Дневник можно класть в контейнеры, передавать персонажам и уничтожать
   обычным способом. Его содержимое и пользовательское имя сохраняются вместе
   с предметом после перезапуска игры или сервера.

Первый записавший персонаж становится владельцем нового дневника. В MP
владельца определяет стабильное имя учётной записи, поэтому другие персонажи
той же учётной записи могут использовать любой принадлежащий ей дневник. Другой
игрок не может посмотреть его содержимое, записать или восстановить прогресс и
переименовать предмет. То же правило действует для последовательных локальных
персонажей в SP.

Запись не расходуется: дневник хранит наибольший когда-либо записанный
заработанный XP каждого навыка и объединение изученных рецептов. Дозапись может
добавить прогресс, но не уменьшает уже сохранённый. Чтение также не уничтожает
дневник, поэтому им можно пользоваться после следующих смертей.

## Правило XP

Записывается только прогресс, заработанный после создания персонажа. Точный XP,
выданный профессией и стартовыми чертами исходного персонажа, сохраняется как
база и не переносится.

```text
заработано = max(0, текущийXP - стартовыйXP источника)
цель       = стартовыйXP нового персонажа + заработано * процент
выдать     = max(0, цель - текущийXP нового персонажа)
```

Поэтому повторное чтение в одной жизни не выдаёт один и тот же XP снова.
Частичный прогресс внутри уровня сохраняется: расчёт использует полный
накопленный XP, а не только целые уровни.

Восстановление вызывает проверенный путь Build 42.20
`addXpNoMultiplier`. Активный множитель от учебной литературы поэтому не
умножает XP, получаемый из дневника. Сообщение об успехе показывает XP, который
игра применила фактически; это важно для встроенных ограничений пассивных
навыков, например Фитнеса.

## Навыки и рецепты

Мод использует явный список ванильных навыков Build 42.20. Навыки других модов
намеренно игнорируются, чтобы неизвестные категорийные перки не были ошибочно
приняты за восстанавливаемые навыки игрока.

Для каждого поддерживаемого ванильного навыка, включая Фитнес и Силу, есть
независимые галочки **записи** и **восстановления**. Поэтому Фитнес и Силу можно
отключать по отдельности, а любой навык — в одном или обоих направлениях.
Первая помощь использует реальный ID Build 42 `Doctor`,
Деревообработка — `Woodwork`, Сбор растений — `PlantScavenging`.

Рецепты, известные при создании персонажа, составляют стартовую базу и не
переносятся. Изученные позже рецепты, включая полученные действием «Изучить» у
предмета, записываются и выдаются только если новый персонаж ещё их не знает.
Одна sandbox-галочка отключает и запись, и восстановление рецептов.

## Настройки песочницы

- процент восстановления: `0–100%`;
- запись и восстановление изученных рецептов;
- отдельные переключатели записи и восстановления каждого поддерживаемого
  ванильного навыка, в том числе независимые настройки Фитнеса и Силы;
- длительность записи и восстановления: `10–5000` единиц действия.

По умолчанию все возможности включены, процент восстановления равен 100%.

## Работа в SP и MP

В SP те же проверки выполняются локально. В hosted MP и на dedicated server
сервер находит запрошенный предмет в инвентаре игрока, проверяет владельца и
рассчитывает операцию по авторитетному состоянию персонажа и предмета. Клиент
не передаёт серверу значения XP или содержимое дневника.

Если подключить мод к уже существующему персонажу, его состояние в момент
первой инициализации мода станет стартовой базой. Более ранний прогресс
намеренно не угадывается и не становится восстанавливаемым.

## Сборка и тесты

Создать сборку для разработки:

```powershell
./build.ps1
```

Создать и установить локальную тестовую сборку:

```powershell
./build.ps1 -LocalTest
```

Запустить автоматические проверки из корня репозитория:

```powershell
.venv\Scripts\python.exe tests\run_lua_tests.py
.venv\Scripts\python.exe tests\validate_project.py
```

Перед релизным тестированием MP см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
и [docs/TEST-MATRIX.md](docs/TEST-MATRIX.md).
